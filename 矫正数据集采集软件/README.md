# C题矫正数据集采集软件

这是一个与现有 C 题上位机完全独立的数据采集程序。程序只接收并保存数据，不发送门锁控制命令，也没有修改现有上位机代码。

## 最重要的距离定义

界面中的“题目实际距离”以直径 60 cm 圆柱的外壁为零点，与题目现场的径向距离定义一致。

- 输入 `1.00 m`：表示圆柱外壁到信标定位点为 1.00 m。
- 根据现场测试，输入 `1.00 m` 时，基站中心距的期望值是 `1.00 + 0.25 = 1.25 m`。
- COM22 原始测距应接近 1.25 m。
- 新采集版本会按主程序相同的顺序处理：`5点中值预滤波 → 场地分段校准 v2 → 30点中值平滑`。

数据文件会同时保留题目实际距离、期望中心距、真正的基站原始值、5点预滤波值、场地分段校准输出和30点中值输出。基础对照列只对距离减25 cm，角度保持基站原始值，因此后续既可以评价新公式，也可以重新分析而不会丢失原始数据。

## 使用方法

1. 先退出原来的 C 题上位机。Windows 的同一个串口不能同时被两个程序占用。
2. 双击 `启动矫正数据集采集软件.cmd`，或直接运行 `发布版\矫正数据集采集软件.exe`。
3. 程序会一直尝试连接：
   - COM21：蓝牙/声光控制板，115200、8N1，只接收；
   - COM22：120°基站，115200、8N1，只接收。
4. 把信标放到实际标定位置。
5. 输入“题目实际距离”和“实际角度”。实际角度以门锁正前方为 0°，左右符号需在整套采集中保持一致。
6. 默认采集 20 秒。点击“开始记录”会清空该点的滤波窗口；前30个有效帧属于预热阶段，CSV中的 `smoothing_ready` 为 `false`。到时会自动停止，也可提前点击“停止记录”。
7. 点击“打开数据文件夹”查看本次数据。

即使开始记录时串口尚未连接，程序也不会停止；它会继续重连，并在连接成功后立即记录数据。

## 每次采集生成的文件

每个标定点会在新的 `数据集_v3_场地分段校准30点中值` 中建立一个独立时间戳文件夹；原来的数据目录不会被覆盖或混入新记录：

- `raw_serial.csv`：COM21、COM22 每次收到的全部原始字节块，含时间、端口、HEX 和可打印 ASCII；
- `measurements.csv`：每个 COM22 定位帧的实际值、原始值、5点预滤波值、标定值、30点中值结果、各阶段误差、滤波预热状态、信标/基站 ID、序号、校验结果和完整原始帧；
- `bluetooth_frames.csv`：COM21 解析出的 AA55 帧、CRC、DIP 放行 ID 和完整原始帧；
- `events.csv`：开始、停止、串口连接和断开事件；
- `session.json`：本次采集条件、距离定义、修正公式、串口参数和数据数量。

真正的原始中心距和原始方位角始终完整保存。界面重点显示“原始值”和“场地分段校准 v2 + 30点中值”的最终结果；前30个有效帧会显示预热进度，满30点后显示“正常·已满30点”。

## 建议的新一轮采集方法

- 每个位置保持相同的基站高度、朝向、支架和周围遮挡条件，信标静止后再开始记录。
- 每点至少记录20秒，建议重复3次；不要移动到下一点后立刻沿用上一点窗口，程序会在每次点击“开始记录”时自动清空滤波。
- 优先采集分区边界两侧：`0.8/1.0/1.2 m`、`1.8/2.0/2.2 m`、`2.8/3.0/3.2 m`，并覆盖 `-45° ~ +45°`。
- 评价当前软件效果时只统计 `smoothing_ready=true` 的行；重新训练标定模型时仍应从 `raw_center_distance_m` 和 `raw_azimuth_deg` 开始，不要只拿平滑结果反复拟合。

## 源代码与验证

- 主程序源码：`src`
- 协议及数据写入自检：`tests`

运行自检：

```powershell
dotnet run --project .\tests\CalibrationCollector.Smoke.csproj -c Release
```

自检会验证基站帧拆包、XOR 校验、蓝牙 CRC、DIP ID、精确分段公式、5点预滤波、30点中值及“输入 1.00 m 对应期望中心距 1.25 m”的数据记录逻辑。
