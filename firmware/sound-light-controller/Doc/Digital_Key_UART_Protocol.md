# 数字钥匙 UART 通信协议

## 1. 链路配置

- 主控 UART0：PA10 TX、PA11 RX
- 波特率：115200
- 数据格式：8N1
- 硬件流控：无
- 多字节整数：低字节在前

主控搭载 4 位 DIP、LED1、LED2 和蜂鸣器。主控每 100 ms 持续发送
DIP 表示的 4 位 ID。定位板计算钥匙距离、方位角和区域判决，再将门锁状态
发回主控。

## 2. 通用帧

| 偏移 | 字段 | 长度 | 说明 |
|---:|---|---:|---|
| 0 | HEAD0 | 1 | 固定 `0xAA` |
| 1 | HEAD1 | 1 | 固定 `0x55` |
| 2 | VERSION | 1 | 当前为 `0x01` |
| 3 | TYPE | 1 | 消息类型 |
| 4 | SEQ | 1 | 每发一帧加 1，允许自然回绕 |
| 5 | LEN | 1 | PAYLOAD 长度，最大 16 |
| 6 | PAYLOAD | LEN | 消息载荷 |
| 6+LEN | CRC_L | 1 | CRC16 低字节 |
| 7+LEN | CRC_H | 1 | CRC16 高字节 |

CRC 使用 CRC-16/CCITT-FALSE：

- 多项式 `0x1021`
- 初值 `0xFFFF`
- 不反射
- 无结果异或
- 计算范围为 `VERSION` 至 PAYLOAD 最后一个字节，不包含两个帧头和 CRC

## 3. 主控到定位板：ID_REPORT (`TYPE=0x10`)

发送周期为 100 ms。

| PAYLOAD 偏移 | 字段 | 说明 |
|---:|---|---|
| 0 | KEY_ID | 仅低 4 位有效，范围 `0x0~0xF` |

定位板用此 ID 进行身份验证，并应将本次检测到或验证的 ID 放入状态帧返回。

例如序号为 0、ID 为 5 的完整帧：

```text
AA 55 01 10 00 01 05 6E C3
```

## 4. 定位板到主控：LOCK_STATUS (`TYPE=0x20`)

载荷固定 9 字节。

| PAYLOAD 偏移 | 字段 | 说明 |
|---:|---|---|
| 0 | KEY_ID | 定位板检测到的钥匙 ID，范围 `0~15` |
| 1 | AUTH | `0` 未判定，`1` 失败，`2` 通过 |
| 2 | ZONE | `0` 无/丢失，`1` 感应区，`2` 迎宾区，`3` 开锁区 |
| 3 | EVENT | 区域变化事件，见下表 |
| 4 | DIST_L | 径向距离，单位 mm，低字节 |
| 5 | DIST_H | 径向距离，单位 mm，高字节 |
| 6 | ANGLE | 有符号 `int8_t` 方位角，单位度 |
| 7 | STATE | 状态标志位 |
| 8 | QUALITY | 定位/无线质量，建议范围 `0~100` |

事件编码：

| EVENT | 含义 |
|---:|---|
| 0 | 状态保持 |
| 1 | 发现钥匙/进入感应范围 |
| 2 | 进入迎宾区 |
| 3 | 进入开锁区 |
| 4 | 离开开锁区 |
| 5 | 离开迎宾区 |
| 6 | 钥匙丢失或离开感应范围 |

STATE 位定义：

| 位 | 掩码 | 含义 |
|---:|---:|---|
| bit0 | `0x01` | 检测到钥匙 |
| bit1 | `0x02` | ID 验证通过 |
| bit2 | `0x04` | 迎宾声光提示开启 |
| bit3 | `0x08` | 门锁已开 |
| bit4 | `0x10` | 门锁已闭 |

定位板应周期发送状态，而不只在区域变化时发送，建议周期为 50~100 ms。
主控连续 500 ms 未收到 CRC 正确的状态帧时进入安全状态：LED1 熄灭、
LED2 点亮、蜂鸣器关闭。

例如：ID=5、验证通过、进入迎宾区、距离 1500 mm、角度 +15°、迎宾提示
开启、门锁闭锁、质量 80，序号为 0：

```text
AA 55 01 20 00 09 05 02 02 02 DC 05 0F 17 50 A4 D9
```

## 5. 主控迎宾判决与声光映射

主控不使用单帧区域结果直接触发声光，而是对 CRC 正确的状态帧进行连续
确认。只有 `AUTH=2` 且 `ZONE=2` 才视为一帧有效的“在迎宾区”结果。

- 当前确认状态不在迎宾区，连续 10 帧均在迎宾区：确认进入迎宾区。
- 当前确认状态在迎宾区，连续 10 帧均不在迎宾区：确认离开迎宾区。
- 确认过程出现相反结果时，连续计数立即清零。

确认进入迎宾区后：

- PA18 LED1 按 250 ms 亮、250 ms 灭的节拍闪烁 3 秒，然后熄灭。
- PA27 蜂鸣器连续响 3 秒，然后关闭。

确认离开迎宾区后：

- PA18 LED1 常亮 3 秒，然后熄灭。
- PA27 蜂鸣器连续响 3 秒，然后关闭。

以上计时均为非阻塞实现，提示期间 UART 仍能继续收发和解析。PB19 LED2
和 PA8 LED3 由开锁区判决状态机控制。

## 6. 主控开锁区判决与 LED 映射

开锁区使用与迎宾区相同的连续 10 帧确认方式。只有 `AUTH=2` 且 `ZONE=3`
才视为一帧有效的“在开锁区”结果。

- 当前确认状态不在开锁区，连续 10 帧均在开锁区：确认进入开锁区，
  PB19 LED2 点亮，PA8 LED3 熄灭。
- 当前确认状态在开锁区，连续 10 帧均不在开锁区：确认离开开锁区，
  PB19 LED2 熄灭，PA8 LED3 点亮。
- 连续确认过程中出现相反结果，计数立即清零。
- 状态通信超时会立即回到安全闭锁显示：LED2 熄灭、LED3 点亮。

## 7. 旧测试帧兼容

主控仍兼容原 OLED 字符测试帧 `FF 2F LEN PAYLOAD XOR CC`，但正式板间通信
应使用本文件定义的 `AA 55` + CRC16 帧。
